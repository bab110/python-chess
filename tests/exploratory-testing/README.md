#### **5.2.3.1 Antisocial Tour: Board Generation, Piece Movement, and Outcome Determination**

**Test Description**
| Test Tour                     | Antisocial Tour: board generation, piece movement, and outcome determination                                                                                                                                                                                                                                                                                                             |
| ----------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Description                   | Explore the standard chess game flow from game start to finish, attempting invalid input/moves at every opportunity presented. This approach should mimic a naïve user’s implementation of the engine and assist in validating that the engine can handle incorrect inputs without failure. This approach should also highlight input instances that lead to non-recoverable exceptions. |
| Test Duration                 | 90 minutes                                                                                                                                                                                                                                                                                                                                                                               |
| Tester                        | Thomas                                                                                                                                                                                                                                                                                                                                                                                   |

To fully validate edge cases, further consideration should be made for the underlying logic to ensure there aren’t gaps in how some pieces are evaluated in edge cases versus another.                                     |
